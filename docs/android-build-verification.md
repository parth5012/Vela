# Android build verification (NDK/SDK) — for a machine with Android Studio

Everything below is **not yet verified**. The environment that produced wayfinder
#293/#297 had no Android toolchain (no `java`, no SDK/NDK, no `cmake`, no
`gradle`), so host-side CMake configure and `g++ -fsyntax-only` were the only
proof available — they prove configure/syntax only, never NDK compile/link,
Gradle packaging, or on-device load. Run this checklist on a machine that has
Android Studio to close that gap.

This is the **build** half. The **runtime** half (pill, model load, extraction
screen, envelope, #299 gate) stays in `PRODUCT.md` → *On-Device Verification
Plan*, steps 4–8.

## Prerequisites

| Thing | Version / note |
|---|---|
| Android Studio | Koala (2024.1) or newer |
| JDK | 17 (ships with Android Studio's JBR) |
| SDK Platform | Android 34 (`compileSdkVersion 34`) |
| **NDK** | **27.1.12297006** — exact. It is pinned in `client/modules/needle/android/build.gradle`; a different side-by-side NDK is silently ignored by that `ndkVersion` field. Install via *Settings → Languages & Frameworks → Android SDK → SDK Tools → NDK (Side by side)*. |
| CMake | 3.22.1 or newer (SDK Manager → SDK Tools → CMake) |
| Node | on `PATH` — CMake configure runs `modules/needle/scripts/fetch-engine.js` through `find_program(... node)`. Missing node ⇒ fail-closed mock, not a failure. |
| Gradle wrapper | generated by prebuild; `client/android/` is gitignored except `settings.gradle`, so never hand-edit it |

Sanity check before starting:

```bash
node -v                      # must print something
sdkmanager --list_installed | grep -Ei 'ndk|cmake'   # or check in Android Studio's SDK Manager
adb devices                  # your arm64 device (see the emulator note below)
```

## Build

```bash
cd client
npm install                        # runs postinstall (patch-package)
npx expo prebuild --clean -p android   # regenerates the gitignored android/ tree
cd android
./gradlew assembleDebug            # Windows: gradlew.bat assembleDebug
```

On Windows, `npm run android:apk` (the existing `scripts/*.ps1` helpers) also
works, but the plain Gradle line above is the one to use when you are proving
the native build — it shows the CMake configure log.

Expected artifact:

```
client/android/app/build/outputs/apk/debug/app-debug.apk     # package com.parth5012.client.dev
```

## What to read in the configure log

`./gradlew assembleDebug --info` (or just watch the `:needle` externalNativeBuild
block) and grep for:

```
Verifying needle engine archive for arm64-v8a via fetch-engine.js
Needle engine archive verified: .../modules/needle/android/engine/needle3/arm64-v8a/libneedle.a
Linking needle engine (needle3, gen 3) for arm64-v8a from ...
```

`Linking needle engine ...` **is** the success line — it means
`HAVE_NEEDLE_ENGINE=1` and the 1.66 MB `libneedle.a` is statically linked into
our `libneedle.so`.

Anything else means the build succeeded but the **native path did not prove
itself**:

| Log line | Meaning | What to do |
|---|---|---|
| `Building with the honest mock fallback (engine archive missing or unverified)` | fetch/verify failed (pin mismatch, corrupt cache, no `node`) | Run `node modules/needle/scripts/fetch-engine.js --model needle3 --abi arm64-v8a` by hand and read the error; a **pin mismatch must never be waved through** — record it, do not re-pin casually |
| `node not found - cannot verify the needle engine archive` | `node` not on PATH for the Gradle process | Fix PATH (Android Studio launched from a desktop shortcut often has a thinner PATH than your shell) |
| `No upstream needle engine archive for ABI x86_64` | **Expected.** `abiFilters` includes `x86_64`, upstream ships no x86_64 `.a` | Nothing — that ABI is mock by design |
| `undefined reference to needle_init/needle_complete/...` | Link failed: the `.a` does not export the expected symbols for this ABI/STL | Stop and record verbatim — do **not** stub the symbols |
| `relocation R_AARCH64_... against ... can not be used when making a shared object; recompile with -fPIC` (or similar PIC error) | Upstream archive is not PIC for this toolchain | Stop and record verbatim — this is exactly the class of failure the map says is unproven |
| Kotlin/`NeedleModule.kt` or `NeedleNative.kt` compile errors | The extraction-screen and `embed()` Kotlin surface has never been compiled | Fix the compile error; that surface was shipped unverified |

Archive sizes to sanity-check against (all fetched from `Cactus-Compute/needle2|needle3`):

- needle3: arm64-v8a **1.66 MB**, armeabi-v7a 1.29 MB, riscv64 3.72 MB
- needle2: arm64-v8a **20.7 MB**, armeabi-v7a 18.0 MB, riscv64 29.2 MB

### Choosing which engine gets linked

Exactly one of needle2/needle3 can be in the link — they export the same
`needle_*` symbols — so the default is **needle3** and selection is a CMake
cache entry (`NEEDLE_ENGINE_MODEL`), not a runtime switch. To prove needle2 as
well, temporarily add

```gradle
arguments "-DNEEDLE_ENGINE_MODEL=needle2"
```

to the `externalNativeBuild { cmake { ... } }` block of
`client/modules/needle/android/build.gradle`, rebuild, **revert the edit** (that
file is tracked; do not commit a flipped default), and confirm the configure log
says `needle2, gen 2`.

## Emulator vs device — this matters for what you can prove

`abiFilters` is `arm64-v8a` + `x86_64`. A normal Android Studio emulator image on
an x86_64 host is **x86_64**, which has **no upstream archive** and therefore
runs the honest mock — a green emulator run proves packaging, not the engine.

To prove the native engine you need an **arm64** target: your physical device
(the usual MIUI phone), or an arm64 system image on an Apple-Silicon host.

## Then do the runtime half

Install only the app itself:

```bash
adb install -r client/android/app/build/outputs/apk/debug/app-debug.apk
```

and follow `PRODUCT.md` → **On-Device Verification Plan**, steps 4–8:

4. Settings → Local AI → the engine pill must read **⚡ Needle Engine: Accelerated (native)**. **Mock Fallback** here means the link never happened — stop; mock text is not model output.
5. Load `Needle-2 45M` and `Needle-3 (20-layer)`, send a chat turn, no `[Mock mode — ...]` prefix.
6. `/settings/extract`: schema-conformant JSON; empty `function_calls[]` (refusal) distinct from `parse_failure`.
7. Observe a `.cact` tool-call envelope (`function_calls`, `reasoning`, `confidence`) on-device.
8. Run the **#299 `needle_embed` quality gate** — still UNRUN. The search UI half stays parked until it passes.

### Policy and hardware limits (do not work around them)

- **No `androidTest` / instrumentation APK without explicit approval.**
  `connectedAndroidTest` installs a companion package
  (`com.parth5012.client.dev.test`); per `client/AGENTS.md` physical-device
  policy this needs an explicit human yes first. This plan installs nothing but
  the app.
- **MIUI blocks `adb shell input`** (`SecurityException: INJECT_EVENTS`), so
  there is no on-device UI automation — a human drives steps 4–8. Read-only
  inspection (`adb logcat`, `pm list packages`, `run-as ... ls`) needs no
  approval.

## What a passing run would and would not prove

**Would:** NDK compile + link of `needle-jni.cpp` against the real `.a`,
`HAVE_NEEDLE_ENGINE=1` at link time, Gradle packaging, the `.so` loading in the
process, both models actually decoding, the Kotlin/JNI extraction and `embed()`
surface compiling and running.

**Would not:** the `needle_embed` paraphrase quality gate (that is step 8, a
separate pass/fail), ladder slice sizes for 4/8/12-layer Needle-3 variants
(unverified, out of scope), or the act/confirm/refuse confidence UX (still
unspecified).
