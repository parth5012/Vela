The Aurora theme system & settings architecture

One glass world, six atmospheres, eight energies. In Aurora, the theme sets the sky, the glass, and the text; the accent sets the aurora — the gradient that tints the send button, the streaming stripe, the user bubble, and the glow. Theme and accent compose: any of the 8 accents can live on any of the 6 themes.

Theme = atmosphereBackground sky, glass opacity, border tone, text scale, and the default aurora pair. Six of them, one language — the six existing theme IDs keep their names so saved settings survive the redesign.
Accent = energyThe aurora gradient, user bubble, primary action, glow, and active state. Eight selectable energies (the existing 8 accent IDs). One picker, applied everywhere the aurora flows.

The six themes

All six render the same chat surface. Every text color sits well above WCAG AA on its sky; muted text is checked separately on the tinted glass it lands on.

Implementation notes (expo-router)

1 · Settings becomes a stack. Replace the single app/settings.tsx with a folder and a native stack: app/settings/index.tsx (the category index above) plus one screen per group — connection.tsx, appearance.tsx, agent.tsx, local-ai.tsx, messaging.tsx, about.tsx. Rows in the index push with router.push('/settings/connection'); system Back returns to the index, so no nested drawer needed.

2 · Theme composition. utils/theme.ts currently returns one flat color object per theme. Extend each entry with the Aurora token set: sky, glass, glassBorder, text/muted/dim, plus aurora: [acc1, acc2] resolved from the active accent. Keep the 6 theme and 8 accent IDs untouched so persisted settings and tests keep passing.

3 · Where each token lands. The send button, streaming stripe, user-bubble gradient, glow and active states all consume aurora; every card, sheet and block consumes glass/glassBorder. One place changes an energy, everywhere follows.

4 · Keep the old surface as fallback. Until every screen is ported, keep the legacy color keys alongside the new ones so partial migration never renders unreadable text.
