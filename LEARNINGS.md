# Learnings

Key learnings, edge cases, and concepts worth remembering for this project.

## Project-Specific Learnings

1. Vela is a single-tenant (one Owner) personal assistant: Telegram, Discord, and Expo/React Native Android client all talk to one FastAPI backend.
2. Backend runtime is Python 3.11 managed with `uv` (see `backend/pyproject.toml`). Run everything through `uv run` or bare `python`.
3. The supervisor pattern uses LangGraph; intents are classified by `agent/router.py` and routed to tools or multi-turn skills (`agent/graph.py`).
4. Memory is server-side and semantic: Supabase PostgreSQL with pgvector, 512-dim embeddings (`backend/db/supabase.py`, `db/schema.sql`).
5. Client is a single Expo project under `client/` (not a monorepo). Has lint/format scripts configured and typecheck via `npx tsc --noEmit`.
6. ADB-connected device is the user's personal phone (MIUI). `adb shell input` is blocked, so UI automation is not an option; prefer read-only inspection.

## Decision Log

Why decisions were made, alternatives considered, consequences.

- **Needle Engine Vendoring (supersedes the old jniLibs/.so plan, #293)**: Upstream ships only static per-ABI `libneedle.a` — there is no `libneedle.so` anywhere — so `client/modules/needle/scripts/fetch-engine.js` downloads the archives into the gitignored `android/engine/<model>/<abi>/` on first build (pinned URL + SHA256 in `scripts/engine.lock.json`, HF `x-linked-etag` is the SHA256), and CMake links them with `add_library(needle_engine STATIC IMPORTED)`, setting `HAVE_NEEDLE_ENGINE=1`. Missing/unfetchable engine ⇒ `HAVE_NEEDLE_ENGINE=0` and the deterministic mock fallback stub still builds (surfaced honestly by the "Mock Fallback" pill). needle2/needle3 export identical `needle_*` symbols, so the model is chosen at **link time** (`-DNEEDLE_ENGINE_MODEL`, default needle3), never at runtime.
- **Universal LocalAgentLoop**: Designed streaming buffer to detect both Needle JSON tool calls and XML tool tags on-device. Evaluates safety with `safetyManager` and executes actions via Android Accessibility / DeviceAgentNative with recursion capped at 5 turns without network transit.
- **Idempotent Device Step Sync**: Offline turns buffer in Drizzle SQLite `operationLog` and synchronize to `POST /api/sync/device-steps` with source gating (`conv.source == "android_client"`) and idempotent upserting into `SyncMessage` and `ToolInvocation`.

## Edge Cases

Known edge cases, gotchas, non-obvious behaviors discovered during work.

- **HTTP Range Preflight vs OOM**: When preflighting model magic bytes with `Range: bytes=0-15`, some remote servers ignore the Range header and return HTTP 200 with the full content length. Always guard against `response.arrayBuffer()` buffering multi-gigabyte models into mobile memory by checking status, content-length, and reader streaming.
- **Path Traversal in Model Filenames**: Naive regex `replace(/[^a-zA-Z0-9._-]/g, '_')` preserves `..`. Basename isolation via `fileName.split(/[\/\\]/).pop()` plus explicit `..` stripping is required before constructing destination storage paths.
- **JNI Null Dereference & CheckJNI Abort**: In JNI native modules, calling `GetStringUTFChars` on null `jstring` or calling `ReleaseStringUTFChars` with null pointers triggers immediate `SIGABRT` crashes under Android's CheckJNI. Always guard with null checks before string conversion.
- **Cross-Source Sync Ingestion Protection**: `/api/sync/device-steps` must validate `conv.source == "android_client"` to prevent unauthorized injection into external channels (Telegram/Discord).
- **Timezone-Naive ISO-8601 Parsing Bias in JS**: Python `datetime.isoformat()` on naive UTC (`utcnow_naive`) outputs without a trailing `Z`. ECMAScript spec dictates date-time strings without timezone offsets are parsed as device local time, causing a shift equal to the user's timezone offset (e.g. 5.5h in IST, 4h in EDT). Client parsing must enforce UTC normalization by appending `Z` if timezone offsets are omitted.
- **SQLite Hydration RangeError on Corrupt Timestamps**: `new Date(Number(row.created_at)).toISOString()` throws an uncaught `RangeError: Invalid time value` if `row.created_at` produces `NaN`, causing local database hydration (`hydrateChatFromLocalDb`) to fail silently for the entire thread. Timestamps from SQLite must be guarded with `Number.isFinite(ms) && ms > 0`.
- **Regeneration In-Memory Timestamp Omission**: When regenerating assistant turns, `handleRegenerate` omitted `created_at` in `addMessage`, causing `message.created_at` to remain `undefined` in memory until restart even though SQLite fell back to `Date.now()`. All client `addMessage` invocations must explicitly assign `created_at: new Date().toISOString()`.
- **LocalModelSpec.size Must Stay in GB Units (#294)**: The free-space checks in `app/settings/local-ai.tsx` and `app/index.tsx` parse `model.size` with `size.match(/([\d.]+)/)` and treat the captured number as **GB** (`parseFloat(...) * 1.2` compared against `freeGB`). A human-friendly `'13.7 MB'` would make the app demand ~16 GB of free space before downloading a 13 MB file. `LOCAL_MODELS` sizes must stay in GB (e.g. `'~0.014 GB'`) until the parser learns units.
- **jest spawnSync Deadlocks an In-Process HTTP Server (#293)**: `child_process.spawnSync` blocks the parent's event loop, so a loopback `http.createServer` living in the same jest worker never accepts the child's request and the spawn times out (`status: null`). Use async `spawn` + awaiting `close` when the spawned process must talk back to a server started by the test itself.
- **HF `x-linked-etag` Is the LFS SHA256 (#293)**: Hugging Face `/resolve/` HEAD responses expose `x-linked-etag: "<sha256>"` (and `x-linked-size`) for LFS-backed files — a first-party pin without downloading. Verified equal to the locally hashed bytes for all 6 needle archives; quote stripping required.
- **jest: spawnSync Deadlocks an In-Process Loopback HTTP Server (#293)**: A test that `spawnSync`s a child which downloads from an `http.createServer` living in the *same* jest worker hangs forever — the blocking `spawnSync` freezes the event loop so the server can never answer (hit the 20 s child timeout 5/5 times). Use async `spawn` + `await` the `close` event instead.
- **Needle engine header/JNI drift (#292/#293)**: Upstream `needle_reset` returns `void`, `needle_free` no longer exists in any shipped archive (calling it is a link error), `needle_init` returns the tokenized static-prefix length so success is `rc >= 0` (the old `rc == 0` check misreads any non-empty prefix as failure), and `needle_last_error()` must only be called after `rc < 0`. needle2 exports only `init/complete/reset/load` — `needle_last_error`/`needle_embed` call sites must be guarded by `NEEDLE_ENGINE_GENERATION >= 3` or a needle2 link fails.
- **HF `x-linked-etag` is the SHA256 (#293)**: For LFS-backed files, `curl -I https://huggingface.co/<repo>/resolve/main/<path>` returns `x-linked-etag` = the LFS object id = SHA256 of the bytes, plus `x-linked-size`. Verified equal to locally hashed downloads for all 6 needle archives.
- **Jest `spawnSync` Deadlocks Against an In-Process HTTP Server (#293)**: `spawnSync` blocks the jest worker's event loop, so a loopback `http.createServer` in the same test process can never answer the child script's request — the child hangs until the spawn timeout and every status assertion fails with `null`. Drive spawned processes with async `child_process.spawn` + a promise (`close` event) whenever the test provides the network endpoint.
- **HF `x-linked-etag` Is the Pinned SHA256 (#293)**: For LFS-backed files, `https://huggingface.co/<repo>/resolve/main/<path>` answers the HEAD with `x-linked-etag: "<sha256>"` and `x-linked-size` — exact values for a lockfile without downloading the body. Still re-hash the downloaded bytes once: the pin is only trustworthy after a byte-level match (all 6 needle archives matched, 2026-09-29).
- **Needle `needle_complete` Failure Detail Lands in the Output Buffer (#293)**: On `rc < 0` the engine writes the human-readable reason into `out` (upstream `needle/__init__.py` decodes the buffer before falling back to `needle_last_error()`). The JNI mirror must read the buffer first, then `needle_last_error()`, then a generic `failed (code N)` — never a bare "error in inference".
- **HF `/resolve/` Redirects Are Cross-Origin, So Same-Origin Redirect Allowlists Fail (#293)**: `huggingface.co/.../resolve/...` 302s to CDNs like `us.aws.cdn.hf.co`, so a "same host only" redirect policy rejects every legitimate download. Enforce scheme policy instead: refuse https→http downgrades on every hop (even to loopback), gate plain http to `NODE_ENV=test`/`--allow-http`, and let the pinned SHA256 authenticate the final bytes regardless of origin.
- **Format-Level Sniffing Cannot Distinguish needle2 from needle3 (#296)**: both 4-byte `.cact` tags (`83 2A E1 05` / `84 2A E1 05`) map to the same `format: 'cact'`, so preflight/validation results that report only `format` lump the two models together — version-aware consumers need a separate `variant` field (`sniffNeedleVariant` → `'needle2' | 'needle3' | null`, null for gguf/task/unknown). Invariant worth testing: `variant !== null` implies `format === 'cact'`.
- **`LOCAL_MODELS.size` Strings Start With `~`, So `parseFloat` Yields NaN (#296)**: `parseFloat('~0.014 GB')` is `NaN`; digit-match first (`size.match(/([\d.]+)/)`, exactly what the GB free-space guard does) before multiplying to bytes. Same units trap as #294: the captured number is GB, never MB.
