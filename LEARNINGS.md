# Learnings

Key learnings, edge cases, and concepts worth remembering for this project.

## Project-Specific Learnings

1. Vela is a single-tenant (one Owner) personal assistant: Telegram, Discord, and Expo/React Native Android client all talk to one FastAPI backend.
2. Backend runtime is Python 3.11 managed with `uv` (see `backend/pyproject.toml`). Run everything through `uv run` or bare `python`.
3. The supervisor pattern uses LangGraph; intents are classified by `agent/router.py` and routed to tools or multi-turn skills (`agent/graph.py`).
4. Memory is server-side and semantic: Supabase PostgreSQL with pgvector, 512-dim embeddings (`backend/db/supabase.py`, `db/schema.sql`).
5. Client is a single Expo project under `client/` (not a monorepo). Has lint/format scripts configured and typecheck via `npx tsc --noEmit`.
6. ADB-connected device is the user's personal phone (MIUI). `adb shell input` is blocked, so UI automation is not an option; prefer read-only inspection.

## Decision Log

Why decisions were made, alternatives considered, consequences.

- **Needle Engine Vendoring (supersedes the old jniLibs/.so plan, #293)**: Upstream ships only static per-ABI `libneedle.a` — there is no `libneedle.so` anywhere — so `client/modules/needle/scripts/fetch-engine.js` downloads the archives into the gitignored `android/engine/<model>/<abi>/` on first build (pinned URL + SHA256 in `scripts/engine.lock.json`, HF `x-linked-etag` is the SHA256), and CMake links them with `add_library(needle_engine STATIC IMPORTED)`, setting `HAVE_NEEDLE_ENGINE=1`. Missing/unfetchable engine ⇒ `HAVE_NEEDLE_ENGINE=0` and the deterministic mock fallback stub still builds (surfaced honestly by the "Mock Fallback" pill). needle2/needle3 export identical `needle_*` symbols, so the model is chosen at **link time** (`-DNEEDLE_ENGINE_MODEL`, default needle3), never at runtime.
- **Universal LocalAgentLoop**: Designed streaming buffer to detect both Needle JSON tool calls and XML tool tags on-device. Evaluates safety with `safetyManager` and executes actions via Android Accessibility / DeviceAgentNative with recursion capped at 5 turns without network transit.
- **Idempotent Device Step Sync**: Offline turns buffer in Drizzle SQLite `operationLog` and synchronize to `POST /api/sync/device-steps` with source gating (`conv.source == "android_client"`) and idempotent upserting into `SyncMessage` and `ToolInvocation`.

## Edge Cases

Known edge cases, gotchas, non-obvious behaviors discovered during work.

- **Workspace Automation Destructive Tool Guarding & Parameter Adherence**: In multi-tool workspace workflows, destructive operations (e.g. `calendar_delete_event`, `calendar_wipe_events`, `gmail_delete_emails`) must be checked against both case-level forbidden lists and a module-level destructive tools set. Furthermore, confirmation checks must match explicit multi-word confirmation or refusal phrases (e.g. "are you sure", "please confirm", "cannot proceed without confirmation") rather than bare substrings like "sure" or "verify" which easily trigger false positive safety passes. In parameter matching, each expected parameter must match at most once across repeated tool calls to ensure `arg_score` cannot exceed 1.0.
- **Ephemeral Memory Retrieval & Negative Case Hallucination Scoring**: Evaluating memory retrieval without production `pgvector` database pollution requires an in-memory cosine distance engine with matching dimensions (512-dim unit-normalized vectors). In RAGAS faithfulness evaluation, negative retrieval cases (where the information was never recorded in memory) must be graded strictly on affirmative refusal cues without falling back to partial ground-truth word matching, preventing hallucinated responses from falsely passing. For positive queries with zero retrieved contexts, the faithfulness metric must fail ungrounded claims immediately.
- **Streaming Client Response Body Consumption on HTTP Errors**: When using HTTPX streaming clients (`httpx.stream`) in evaluation harnesses, reading `resp.text` on non-200 responses without first calling `resp.read()` causes `httpx.ResponseNotRead` exceptions. Always call `resp.read()` prior to accessing error text on streamed responses.

- **Tautological Assertions in LLM Trajectory Evaluation**: When grading autonomous browser trajectories, comparing expected output keys to expected outcome strings within the same test case produces a tautological assertion that always passes regardless of what the agent actually observed in the browser DOM. Ground-truth evaluation must strictly assert against actual observations produced by the terminal action step in the DOM snapshot.
- **Alternating Cyclic Traps vs Linear Loops**: Simple k-repeat detectors fail to catch oscillating A-B-A-B button toggling (e.g. sorting asc <-> desc) or slow pagination query drift across URL offsets. Dedicated period-L sliding window cycle detection and URL query parameter tracking are required to catch cyclic traps. In addition, pagination drift URL tracking must be strictly bounded to `navigate` actions so that button/element click toggles (like asc/desc) remain classified as `alternating_cycle` rather than premature pagination drift.
- **DeepEval GEval Execution vs Heuristic Separation**: In offline or CI environments without active LLM provider keys, attempting to evaluate trajectories via DeepEval `GEval` without an explicit mock or live LLM model will fail. Trajectory evaluators must instantiate `GEval` with `SingleTurnParams` and formatted trajectory test cases when a model is provided, while maintaining a deterministic offline heuristic fallback that reports its scores under separate explicit metrics (`heuristic_avg_score` alongside `geval_avg_score`) and surfaces the active `evaluation_mode`.

- **Drizzle ORM expo-sqlite Migrator Empty Statement Crash**: `drizzle-orm/expo-sqlite/migrator.js` splits migrations strictly on `--> statement-breakpoint` without trimming or filtering empty queries. If any migration file ends with a trailing breakpoint, an empty query string is passed to `session.run(sql.raw(''))`. In `expo-sqlite`, preparing an empty string sets the C++ `sqlite3_stmt*` pointer to `NULL`. When `runSync()` executes, `NativeStatementBinding.sqlite3_clear_bindings()` invokes `sqlite3_clear_bindings(NULL)`, causing an immediate `SIGSEGV` crash (`exsqlite3_clear_bindings+20`) in `libexpo-sqlite.so` on Android launch. All migration files must omit trailing breakpoints, and `initializeDatabase` in `client/db/client.ts` must sanitize migration SQL strings to filter empty statements and deduplicate concurrent executions.
- **HTTP Range Preflight vs OOM**: When preflighting model magic bytes with `Range: bytes=0-15`, some remote servers ignore the Range header and return HTTP 200 with the full content length. Always guard against `response.arrayBuffer()` buffering multi-gigabyte models into mobile memory by checking status, content-length, and reader streaming.
- **Path Traversal in Model Filenames**: Naive regex `replace(/[^a-zA-Z0-9._-]/g, '_')` preserves `..`. Basename isolation via `fileName.split(/[\/\\]/).pop()` plus explicit `..` stripping is required before constructing destination storage paths.
- **JNI Null Dereference & CheckJNI Abort**: In JNI native modules, calling `GetStringUTFChars` on null `jstring` or calling `ReleaseStringUTFChars` with null pointers triggers immediate `SIGABRT` crashes under Android's CheckJNI. Always guard with null checks before string conversion.
- **Cross-Source Sync Ingestion Protection**: `/api/sync/device-steps` must validate `conv.source == "android_client"` to prevent unauthorized injection into external channels (Telegram/Discord).
- **Timezone-Naive ISO-8601 Parsing Bias in JS**: Python `datetime.isoformat()` on naive UTC (`utcnow_naive`) outputs without a trailing `Z`. ECMAScript spec dictates date-time strings without timezone offsets are parsed as device local time, causing a shift equal to the user's timezone offset (e.g. 5.5h in IST, 4h in EDT). Client parsing must enforce UTC normalization by appending `Z` if timezone offsets are omitted.
- **Eval Seams & Fail-Closed Execution**: System-level evaluations must never drive destructive production tools (e.g. Gmail sending, device uninstall, pgvector memory creation). Injecting an eval interceptor in `backend/agent/graph.py` via `VELA_EVAL_MODE=1` ensures tool executions fail closed to dry-run mocks and bypass persistent `Experience` table insertions.
- **DeepEval Conversational Metric Typing & Dynamic Config**: DeepEval 4.3.1 `ConversationalTestCase` requires a list of `Turn` or dict (not `LLMTestCase`), and custom metrics must inherit from `BaseConversationalMetric` implementing `measure(test_case: ConversationalTestCase) -> float` and `is_successful() -> bool`. In addition, when testing gate overrides, configuration objects instantiated at module import time (`SystemEvalConfig`) do not re-evaluate `os.environ` changes unless dynamic environment lookups (`os.getenv`) are explicitly checked in dispatcher evaluation entry points.
- **Isolated Thread Namespaces & Eval Turn Memory DB Bypass**: To prevent multi-turn eval runs from polluting the SQLite/PostgreSQL `Experience` table used by `build_recent_messages`, all eval threads must adopt the `eval-thread-{id}` namespace convention. In `backend/agent/main.py` and `backend/agent/graph.py`, checking `is_eval = os.getenv("VELA_EVAL_MODE") == "1" or str(thread_id).startswith("eval-")` guarantees zero persistent inserts into `Experience`, strictly isolating production memory from test fixtures.
- **Eval Thread History Retention vs DB Pollution**: When bypassing database persistence (`Experience` table writes) during system evaluation runs to avoid memory poisoning, `/chat/message` must maintain conversation turns in an in-memory session store keyed by `payload.thread_id`. Otherwise, multi-turn eval runs evaluate each turn in complete isolation without cumulative context.
- **Alternative Refusal Keywords vs Cumulative Factual Recall in DeepEval**: Standard recall metrics compute `recalled / len(expected)`, expecting all listed facts to be present. In security and thread isolation evaluations, expected tokens represent disjunctive alternative refusal phrases (e.g. `["don't know", "haven't shared", "no record"]`). A metric operating on isolation cases must evaluate `match_mode="any"` so recalling any valid refusal indicator counts as full isolation success without penalizing the agent for omitting alternative wordings.
- **Python Subpackage Runner Collisions**: Pytest inserts the directory of the running test into `sys.path`. If subpackages all name their entry points `runner.py`, importing `from runner import ...` resolves to the local subpackage rather than the root runner, triggering circular import errors. Separating dispatch into `dispatcher.py` and models into `common.py` resolves namespace shadowing.

- **SQLite Hydration RangeError on Corrupt Timestamps**: `new Date(Number(row.created_at)).toISOString()` throws an uncaught `RangeError: Invalid time value` if `row.created_at` produces `NaN`, causing local database hydration (`hydrateChatFromLocalDb`) to fail silently for the entire thread. Timestamps from SQLite must be guarded with `Number.isFinite(ms) && ms > 0`.
- **Regeneration In-Memory Timestamp Omission**: When regenerating assistant turns, `handleRegenerate` omitted `created_at` in `addMessage`, causing `message.created_at` to remain `undefined` in memory until restart even though SQLite fell back to `Date.now()`. All client `addMessage` invocations must explicitly assign `created_at: new Date().toISOString()`.
- **LocalModelSpec.size Must Stay in GB Units (#294)**: The free-space checks in `app/settings/local-ai.tsx` and `app/index.tsx` parse `model.size` with `size.match(/([\d.]+)/)` and treat the captured number as **GB** (`parseFloat(...) * 1.2` compared against `freeGB`). A human-friendly `'13.7 MB'` would make the app demand ~16 GB of free space before downloading a 13 MB file. `LOCAL_MODELS` sizes must stay in GB (e.g. `'~0.014 GB'`) until the parser learns units.
- **jest spawnSync Deadlocks an In-Process HTTP Server (#293)**: `child_process.spawnSync` blocks the parent's event loop, so a loopback `http.createServer` living in the same jest worker never accepts the child's request and the spawn times out (`status: null`). Use async `spawn` + awaiting `close` when the spawned process must talk back to a server started by the test itself.
- **HF `x-linked-etag` Is the LFS SHA256 (#293)**: Hugging Face `/resolve/` HEAD responses expose `x-linked-etag: "<sha256>"` (and `x-linked-size`) for LFS-backed files — a first-party pin without downloading. Verified equal to the locally hashed bytes for all 6 needle archives; quote stripping required.
- **jest: spawnSync Deadlocks an In-Process Loopback HTTP Server (#293)**: A test that `spawnSync`s a child which downloads from an `http.createServer` living in the *same* jest worker hangs forever — the blocking `spawnSync` freezes the event loop so the server can never answer (hit the 20 s child timeout 5/5 times). Use async `spawn` + `await` the `close` event instead.
- **Needle engine header/JNI drift (#292/#293)**: Upstream `needle_reset` returns `void`, `needle_free` no longer exists in any shipped archive (calling it is a link error), `needle_init` returns the tokenized static-prefix length so success is `rc >= 0` (the old `rc == 0` check misreads any non-empty prefix as failure), and `needle_last_error()` must only be called after `rc < 0`. needle2 exports only `init/complete/reset/load` — `needle_last_error`/`needle_embed` call sites must be guarded by `NEEDLE_ENGINE_GENERATION >= 3` or a needle2 link fails.
- **HF `x-linked-etag` is the SHA256 (#293)**: For LFS-backed files, `curl -I https://huggingface.co/<repo>/resolve/main/<path>` returns `x-linked-etag` = the LFS object id = SHA256 of the bytes, plus `x-linked-size`. Verified equal to locally hashed downloads for all 6 needle archives.
- **Jest `spawnSync` Deadlocks Against an In-Process HTTP Server (#293)**: `spawnSync` blocks the jest worker's event loop, so a loopback `http.createServer` in the same test process can never answer the child script's request — the child hangs until the spawn timeout and every status assertion fails with `null`. Drive spawned processes with async `child_process.spawn` + a promise (`close` event) whenever the test provides the network endpoint.
- **HF `x-linked-etag` Is the Pinned SHA256 (#293)**: For LFS-backed files, `https://huggingface.co/<repo>/resolve/main/<path>` answers the HEAD with `x-linked-etag: "<sha256>"` and `x-linked-size` — exact values for a lockfile without downloading the body. Still re-hash the downloaded bytes once: the pin is only trustworthy after a byte-level match (all 6 needle archives matched, 2026-09-29).
- **Needle `needle_complete` Failure Detail Lands in the Output Buffer (#293)**: On `rc < 0` the engine writes the human-readable reason into `out` (upstream `needle/__init__.py` decodes the buffer before falling back to `needle_last_error()`). The JNI mirror must read the buffer first, then `needle_last_error()`, then a generic `failed (code N)` — never a bare "error in inference".
- **HF `/resolve/` Redirects Are Cross-Origin, So Same-Origin Redirect Allowlists Fail (#293)**: `huggingface.co/.../resolve/...` 302s to CDNs like `us.aws.cdn.hf.co`, so a "same host only" redirect policy rejects every legitimate download. Enforce scheme policy instead: refuse https→http downgrades on every hop (even to loopback), gate plain http to `NODE_ENV=test`/`--allow-http`, and let the pinned SHA256 authenticate the final bytes regardless of origin.
- **Format-Level Sniffing Cannot Distinguish needle2 from needle3 (#296)**: both 4-byte `.cact` tags (`83 2A E1 05` / `84 2A E1 05`) map to the same `format: 'cact'`, so preflight/validation results that report only `format` lump the two models together — version-aware consumers need a separate `variant` field (`sniffNeedleVariant` → `'needle2' | 'needle3' | null`, null for gguf/task/unknown). Invariant worth testing: `variant !== null` implies `format === 'cact'`.
- **`LOCAL_MODELS.size` Strings Start With `~`, So `parseFloat` Yields NaN (#296)**: `parseFloat('~0.014 GB')` is `NaN`; digit-match first (`size.match(/([\d.]+)/)`, exactly what the GB free-space guard does) before multiplying to bytes. Same units trap as #294: the captured number is GB, never MB.
- **Schema-as-only-Tool Extraction (#298)**: Passing the Owner's JSON schema as the *only* declared tool to `needle_init` makes the constrained decode grammar itself the conformance guarantee — no prompt-based "please output JSON" jailbreaking. The response envelope's empty `function_calls[]` is then the model's *refusal* (or missing required properties), a distinct terminal state from `parse_failure` — never conflate them in UI or tests (upstream cactuscompute structured-extraction blog, #290 option 1).
- **Empty-String Tool Declarations Must Collapse to `"[]"` at the JNI Boundary (#298)**: The TS wrapper passes `''` for absent optional strings, so Kotlin's `String?` arrives as a *non-null empty* `jstring` after `GetStringUTFChars`. Guard with `(ptr && ptr[0] != '\0') ? ptr : "[]"` so the chat path feeds `needle_init` the exact bytes it saw before the plumbing existed — a raw `""` would silently change chat behavior rather than fail loudly.

- **drizzle-kit Single-Statement Migrations Have No `--> statement-breakpoint`, but the #147 Guard Requires One (#299)**: drizzle-kit 0.31 only emits breakpoints *between* statements, so a one-statement migration (`0005_message_vectors.sql`) ships with no marker at all and `__tests__/migrations.test.ts` fails on it. Repo precedent (`0004_checkin_offline_queue.sql`, also single-statement) ends with a trailing `--> statement-breakpoint` — append it; the expo migrator splits on the marker and SQLite accepts the resulting empty final statement.
- **Editing Only a `.sql` Migration Leaves Jest's Transform Cache Stale (#299)**: `babel-plugin-inline-import` inlines the SQL text into `migrations.js` when jest transforms that file, and the cache key covers `migrations.js` + babel config — not the imported `.sql`. Symptom: `npx jest --no-cache` passes while a normal run keeps failing on the old SQL. Fix: `npx jest --clearCache`.
- **FTS5 `MATCH`'s Left Operand Must Be the Table Name, Not the Alias (#299)**: `FROM messages_fts f ... WHERE f MATCH ?` fails with "no such column: f", while the unqualified `WHERE messages_fts MATCH ?` (with `f` used only for `f.rank`) is valid SQLite. The existing dead-code query in `messageSearch.ts` is correct — don't "tidy" `MATCH` onto the alias.
- **The Old `cactus-ai/needle-45m` URL Is Dead (HTTP 401) (#294/#297)**: the pre-map model host answers 401, so a cached/remembered `cactus-ai` URL is a silent download failure, not a 404 you can notice up front. Live models are `Cactus-Compute/needle2` and `Cactus-Compute/needle3`; `rg cactus-ai` over source must return 0 hits.
- **needle2 and needle3 Contexts Are Not the Same "256" (#294/#297)**: needle2 is 2048 context with a 256-token sliding window; needle3 is 8192 with a 1024-token local window and a 256-token KV window. Quoting "256" as *the* context conflates two different numbers that happen to share a 256 somewhere — always cite max context (2048 / 8192) and name which window you mean.
- **"All 3 architectures" Is a Wrong Frame for the Needle Lineup (#290/#297)**: Needle-1 (26M safetensors) was decided out of scope in #290 (format/contract/licence mismatch, no `.cact` loader path). Only Needle-2 45M and Needle-3 (20-layer) ship — docs, tests, and UI copy that say "3 models" are incorrect, even though the wayfinder map's title still says "3 architectures".
- **Host-Side CMake/`g++ -fsyntax-only` Is Not Android Proof (#293/#297)**: with no Android NDK/SDK in the dev environment, a green host configure, a `g++ -fsyntax-only` pass over the JNI bridge, and 62 green jest suites (581 tests) still leave NDK compile/link, Gradle packaging, and on-device load unproven. Record those as UNVERIFIED and hand a human the explicit fetch-at-build → `assembleDebug` → install → Accelerated-pill plan instead of implying the native path works.
- **GitHub Stacked PR Cascades on Delete-Branch (#300-#309)**: Merging a PR with `--delete-branch` when downstream PRs in a stack target that branch causes GitHub to automatically close the child PRs instead of retargeting them. In gh 2.46.0, `gh pr edit --base` crashes due to Projects (classic) deprecation, so child PRs must be retargeted via REST (`gh api -X PATCH repos/.../pulls/<n> -f base=main`) before deleting parent branches.
- **Hardcoded Date Timebombs in Rolling History Queries (#310)**: Tests asserting `get_briefing_history(days=30)` with hardcoded ISO dates (e.g. `2026-08-30`) will silently rot and fail with `assert 0 == 1` once the runner date advances past 30 days after the fixture date. Use `date.today().isoformat()` for test fixture dates that are queried via rolling history windows.
- **Node 20 Missing `node:sqlite` in CI (#311)**: Built-in `node:sqlite` was introduced in Node 22.5. Tests using `node:sqlite` fail in CI if runner actions set up Node 20. Update CI workflows to Node 24 where `node:sqlite` is stable without flags.
- **Stacked PR Rebase Conflicts on Rebased Ancestor Commits**: When stacking PRs where parent PRs are rebase-merged to `main` with new commit SHAs, child branches keep the old commit SHAs in their history, which causes GitHub's rebase-merge to reject the PR with merge conflicts. Rebase/cherry-pick the child's unique commits cleanly onto the latest `origin/main` and force-push to the PR branch before merging.
- **Shizuku UserService `destroy` Is AIDL Transaction 16777114, Not 16777115**: the Shizuku-API README quotes the server-side code 16777115 but says "use 16777114 in aidl" — the AIDL must declare `void destroy() = 16777114;` (explicit transaction-code syntax, accepted by current build-tools) and the implementation must call `System.exit(0)`, because Shizuku never kills user-service processes itself.
- **`Shizuku.newProcess` Is Deprecated — UserService Is the Supported Exec Path**: changelog 13.1.1 announced "Prepare to remove `Shizuku#newProcess`… developers should have to use `UserService` instead". Beyond future-proofing, a UserService runs the allowlist re-validation *inside* the privileged process, which a text-based `newProcess` cannot do.
- **Pre-Dispatch Failures Must Be Exit Codes, Not Exceptions**: `deviceActionExecutor` reports any throw after dispatch as `indeterminate` (may have taken effect → verify before retry). If readiness/bind problems also threw, every "server not running" would read as indeterminate and invite blind retries on the Owner's phone. So the native layer returns `exit=125/126/127` *strings* for anything that never ran; only an `execOp` RemoteException propagates.
- **Sui Has No Manager App — a Live Server Must Be Authoritative in Status Derivation**: `installed=false, serverRunning=true` is the root/Sui shape; gating on `installed` first blocks rooted users. `deriveShizukuState` checks `serverRunning` first and consults `installed` only when the server is down (to split `app_missing` from `server_stopped`).
- **Shizuku User Services Are Instantiated by Class NAME via Reflection — R8 Needs Consumer Keep Rules**: the server does `Class.forName` on a string R8 can never see, so a minified build silently loses `ShizukuOpsService` and fails only on device. Ship `consumer-rules.pro` keep entries from the library module so the app inherits them.
- **AGP 8 Needs `buildFeatures.aidl true`, and Shizuku 13.1.x Needs Desugaring below API 26**: aidl generation is off by default since AGP 8 (silent "cannot find symbol" on the Stub otherwise), and Shizuku-API 13.1.0 made core library desugaring mandatory at minSdk < 26 — both belong in the *library* module's `build.gradle`, not only the app's.
- **drizzle-kit Journal `when` Must Be Monotonically Increasing, and Hand-Edited Timestamps Must Stay In the Future (#356)**: `expoSqliteDrizzle`'s `migrate()` gates on `__drizzle_migrations.created_at < journal.folderMillis`, so a hand-set `when` that is *smaller* than an earlier migration's `when` makes SQLite silently refuse to run the new one — every fresh test DB still passes because the test harness applies SQL directly. After any hand edit of `meta/_journal.json`, assert `journal[idx].when > journal[idx-1].when` in a test; 0006's future-dated `when` (1791300000000) required bumping 0007 to 1791400000000.
- **drizzle-kit Column Rename Prompts Need a TTY — Drive It Through a `pty` Wrapper (#356)**: `drizzle-kit generate` interactively asks "column `persona` in table `threads` renamed to `agent`?" and a plain captured run deadlocks on the prompt (no output, no exit). `/tmp` helper script opens the process with `pty.spawn`, sends `ArrowDown` + `Enter` to choose "rename column", and lets the kit write the `ALTER TABLE ... RENAME COLUMN` DDL + snapshot itself — never hand-write the rename SQL or the `meta/*_snapshot.json` (kit's snapshot is the upgrade-diff source of truth).
- **`rg persona` Matches the `'personal assistant'` Agent-Id Literal, So the Acceptance Grep Is Literally Unsatisfiable (#356)**: the repo's default agent id *contains* "persona" as a substring, so `rg "persona" client/db/` never returns empty even after a perfect rename. The honest zero-hit check is `rg -w persona client/db/*.ts` (word-boundary, code only); remaining raw hits belong exclusively to immutable historical migrations/snapshots and the rename DDL itself.
- **pnpm 12 Ignores `.npmrc`'s `node-linker=hoisted`, Leaving `@types/node` Unresolved (#356)**: a fresh worktree has no `node_modules`, and the default isolated linker hoists differently than CI expects — `npx tsc --noEmit` then floods with TS2688 "cannot find type definition file". Fix with `pnpm install --node-linker=hoisted` (matches `.npmrc`) before trusting any typecheck baseline; capture a pre-change `tsc` baseline file and diff against it, since this branch carries pre-existing errors.
- **A Seeder's "Never Revert User Edits" Guard Silently Blocks Future Seed Updates (#356/#360)**: `PRESET_UPSERT_SQL` originally guarded with `WHERE agents.is_preset = 1 AND agents.system_prompt = excluded.system_prompt`, which preserves any divergent stored prompt but also means a *future release* changing the bundled prompt can never reach existing installs (stored ≠ new seed → guard false → no update). The two goals are indistinguishable at upsert time without a stored seed-version marker. Resolution: presets are app-owned read-only templates (`is_preset = 1`, UI offers Duplicate only), so the guard is just `WHERE agents.is_preset = 1` — presets re-sync to the bundle every launch, and "never revert a user edit" is owned exclusively by `is_preset = 0` rows (test `never overwrites a user-owned row`). Flipping the guard always requires rewriting the paired test in the same commit, and an OCR/linter "remove this redundant condition" suggestion on a seeder is never purely cosmetic — read what the condition is actually buying before accepting it.
- **`isLocalModelLoaded` Is Module-Level State, So Every Non-Chat Entry Point Is a Cold Start (#361)**: `streamLocalLlmResponse` throws `Local model not loaded` unless `initializeLocalModel()` ran first, and the flag lives in plain module scope — a background/headless JS context (expo-task-manager) or a manual task run before the chat screen ever opens always sees `false`. Unit tests mock `../localLlm` and therefore never catch it, so the failure only shows up on device. Any entry point other than chat (`taskRunner`, future widgets/shortcuts) must `await initializeLocalModel()` itself and translate init failure into the same human-readable fail-fast reason the mode gate uses.
- **A Scheduler-Level Credential Gate Silently Disables Every Mode (#363)**: `backgroundTasks.ts` returned `Failed` before selecting any task whenever `apiUrl`/`apiKey` were empty, so adding a per-task connection mode did nothing until that gate was deleted — credential checks belong at the per-task dispatch site (inside `runTask`, guarded by `mode === 'server'`), never at the scheduler entry. The tell is a test that mocks config with empty credentials: if the handler returns before the due-task SELECT, the gate is still blanket-level.
- **Test Files Are Consumers Too — "Unused Export" Scans Must Cover `tests/`**: an AST/source scan of production imports flagged `webview_browser.PENDING_TASKS` as dead, but `tests/test_webview_concurrency.py` uses it as a fixture (`wb.PENDING_TASKS.clear()`); deleting it turned a passing suite red with an `AttributeError` that no typecheck or client test could catch. Grep the whole tree (including `tests/`, `__tests__/`, and docs) before purging any export, and run pytest even for "obviously dead" Python deletions.
- **Extracted Shared Helpers Must Preserve Per-Call-Site Divergences**: the three server dispatch blocks in `app/index.tsx` looked identical, but the new-thread path intentionally omits the optimistic `setThreads` title update — naively unifying all three would change UI behavior. The extracted `runServerStream` therefore takes an *optional* `threads` param (new-thread passes none), and behavior-preserving dedup means diffing each call site's arguments and side effects first, not just its shape. Lint-warning parity is likewise set-based: compare the warning set (via a `git stash` HEAD run), never line numbers, since refactors legitimately shift them.
- **The Edit Tool Matches oldString with Whitespace Flexibility — a Badly-Indented NewString Corrupts the File Silently**: a styles-extraction edit whose `oldString` omitted the 2-space indent on `container: {` still *matched* the indented original, and the literal (un-indented) `newString` was applied, mangling two lines in one call. The edit reported success; only an immediate `git diff` caught it. Rule: after any structural edit, run `git diff --stat`/`git diff` on the file *before* the next step; recover with `git checkout -- <file>` (safe pre-commit) and redo with full-line anchors — never try to hand-patch the damage.

- **Async Re-entrancy Guards Need a Synchronous Abort Flag, Not Just an Awaited Promise (#425 model gate)**: in `ResumableModelDownloader`, `start()` registers its `await this.initPromise` continuation *before* any `pause()`/`cancel()` called afterwards can register theirs (FIFO microtask ordering), so checking `isDownloading` after `await this.initPromise` can never observe a cancel issued during init — the download would still start. ## 2026-10-27 — Abort is a protocol terminus, not normal completion (map #480 round-1 panel)
- When a streaming producer is cancelled, the cancellation must travel through the SAME-queue as a distinct marker (`__cancelled__` → SSE `type:thread_stopped`), never as the completion sentinel. Funneling cancel through the normal `None` terminator silently triggered downstream completion work (LLM title generation) after owner-abort and made clients unable to distinguish a stop from a finish. Four independent reviewers found different facets of "cancel pretending to be completion" (fake `done`, stale persist snapshot, placeholder pruning of the wrong turn) — the general lesson: side-effects of an aborted flow (persist, finalize, prune) must be scoped to the turn in flight, keyed by identity captured at start-time (stream generation, placeholder message id), not by "whatever happens to be last".
- Persist-before-drain loses buffered tail: setting `persisted = True` from a stale snapshot races the still-draining queue. Correct order: cancel producer → settle producer task → let the consumer finalize (it holds the FULL accumulated response incl. queued tail) → fallback persist only if not already persisted. Snapshot-based "already done" flags must be observed, not trusted, after cancellation.
- Test integrity: hand-copied UI/logic clones in tests (ChatSendButton lambdas, test-local abort-throw callbacks) keep suites green while production branches can be deleted. When a decision function already exists (`handleSendPressAction`), the real handler should delegate to it and the test drives the real export — clone-by-construction disappears.

## 2026-10-28 — Stacked-PR landing hazards (map #480 merge run)
- `gh pr merge --delete-branch` on a stacked PR deletes its head branch, which is the CHILD PR's base — GitHub then auto-closes the child (`base_ref_deleted` event) and neither `gh pr edit --base main` nor `gh pr reopen` recover it. Land stacks WITHOUT `--delete-branch`, or file replacements from the rebased branch (content survives at the branch tip).
- GitHub's rebase-merge of a stacked PR merges into the PR's BASE BRANCH, not `main` — bottom-up cascade lands layers in intermediate branches; `main` only advances when a PR whose base is `main` merges. Verify where the merge commit actually landed (`git log origin/main`) before trusting "MERGED" state.
- After a layer commit is edited during conflict resolution, the child chain still contains the old-copy commit whose patch-id no longer matches — rebase won't auto-drop it and will conflict. Resolve by `git rebase --skip` (the new base already supersedes it), then continue.
- When rebasing a streaming-engine layer over a display fast-path store (WF-455's `useActiveStreamStore`): tokens diverted to the ephemeral display buffer bypass the persisted store's persist scheduling, so the finalize fold MUST commit through the persisting path (`updateLastMessageContent` — sanitize + clear debounce + saveMessage), and a new overlay start must fold stale overlay text into its owning message first (cross-thread background streaming otherwise wipes the first stream's diverted tokens and prunes its empty-looking placeholder). One divert-aware sink (`streamController.deliverTokens`) covering throttle/flush/finalize + mid-stream error paths keeps all write paths coherent.

## 2026-10-30 — A lint gate has to answer for the change, not for the repo
